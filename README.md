# DiceFlow

## Описание

**DiceFlow** — ассистент для варгеймов, который делает броски кубиков быстрее, удобнее и приятнее.

Основная идея — превратить последовательность бросков и модификаций результатов в быстрый и наглядный игровой процесс с хорошим Game Feel.

## MVP

MVP работает только с шестигранными кубиками (D6).

Основной цикл:

**бросок → результат → модификации → следующий бросок**

После броска игрок может:
- выбирать отдельные кубики, группы или диапазоны групп;
- добавлять кубики;
- удалять кубики;
- перебрасывать выбранные кубики;
- перемещать выбранные кубики в любую группу.

## Кубики

Каждый кубик имеет:
- тип;
- значение;
- состояние выбора;
- визуальное состояние.

После броска кубик получает случайное значение и перемещается в соответствующую группу.

Выбранные кубики визуально выделяются и слегка дрожат.

Способы выбора:
- нажатие на отдельный кубик;
- нажатие на другой кубик — выбор диапазона между ними;
- свайп с кубика на кубик — выбор диапазона, обновляется в реальном времени по мере движения пальца;
- нажатие на уже выбранный кубик — снятие выделения;
- нажатие на группу — выбор всех кубиков в группе;
- свайп по значениям групп — выбор диапазона групп, обновляется в реальном времени;
- удержание около секунды и перетаскивание — перемещение кубика между группами (захваченный кубик увеличивается и следует за курсором; несколько кубиков собираются вокруг курсора; плашка целевой группы подсвечивается; если кубики отпущены не над новой группой, они возвращаются на исходные места, а выделение снимается).

## Игровой стол

Игровой стол отображает результаты броска и позволяет удобно работать с большими группами кубиков.

Для D6 стол разделён на шесть горизонтальных зон: от 6 сверху до 1 снизу.

После получения значения кубик автоматически перемещается в соответствующую зону.

Каждая группа показывает количество кубиков.

Кубики, появившиеся в результате модификаций после броска, визуально отделяются от исходных. Кубики, относящиеся к одной операции, получают соответствующий цветовой оттенок.

Пример:

┌─────────────────────────────────────┐
│ 20d6 → Roll → 4d6:6 → ReRoll       │
│          → 2d6:6 → Explode          │
├─────────────────────────────────────┤
│                                     │
│ 6:  🎲 🎲 🎲 🎲 + ◆ ◆        = 6   │
│ 5:  🎲 🎲 🎲                   = 3   │
│ 4:  🎲 🎲 🎲 🎲 🎲             = 5   │
│ 3:  🎲 🎲 🎲 🎲 🎲 + ◆        = 6   │
│ 2:  🎲 🎲 🎲 🎲               = 4   │
│ 1:  🎲 🎲 🎲 🎲 + ◆          = 5   │
│                                     │
├─────────────────────────────────────┤
│ [Roll] [ReRoll] [Add 1] [Move 1]  │
│                                     │
│ [Delete 1] [Undo] [Redo] [Clear]   │
└─────────────────────────────────────┘

`◆` условно обозначает кубики, связанные с операцией. В реальном интерфейсе они получают соответствующий цветовой оттенок.

## Управление

- **Roll** — начать новую итерацию: бросить выбранные кубики и удалить все невыбранные. Кнопка неактивна, если ничего не выбрано.
- **ReRoll** — перебросить выбранные кубики в рамках текущей итерации. Если ничего не выбрано, перебрасываются все кубики на столе.
- **Add X** — добавить X кубиков со случайным значением. X равен количеству выбранных кубиков или 1, если ничего не выбрано.
- **Move X** — переместить X выбранных кубиков в выбранную группу.
- **Delete X** — удалить X выбранных кубиков. Если ничего не выбрано, удалить последний добавленный кубик.
- **Undo** — отменить последнее действие.
- **Redo** — вернуть отменённое действие.
- **Clear** — полностью очистить стол после подтверждения.

Undo и Redo переходят по истории действий: отменяемы все действия, кроме выбора. После нового действия ранее отменённая ветка удаляется. Последовательные одинаковые действия объединяются в один отменяемый шаг (например, пять нажатий «Add 1» — одно действие).

## Добавление кубиков

Если на столе нет кубиков, отображается подсказка:

`Swipe Finger to Add or Reduse Dices`

Свайп работает только когда стол полностью пуст — после запуска или после **Clear**.

Пользователь может провести пальцем по столу, чтобы добавлять или уменьшать количество кубиков.

Кубики сразу появляются в соответствующих группах во время движения пальца.

Выданные значения запоминаются: кубик, удалённый и затем снова добавленный в рамках того же жеста, возвращается с прежним значением.

После того как пользователь убрал палец, количество кубиков фиксируется, и весь жест считается одним действием.

## История

История записывает каждое действие игрока: Roll, ReRoll, Add, Delete, Move и Clear.

Undo и Redo переходят по этой же истории и не записываются как отдельные записи.

Удалённые значения запоминаются (LIFO): кубик, добавленный без явного значения, берёт значение последнего удалённого кубика. Память очищается действиями Roll, ReRoll и Clear.

Add и Delete в рамках одного раунда сворачиваются в одну net-запись: «Add 5 → Delete 2 → Add 1» записывается как «Add 4».

Пример строки броска:

20d6 → Roll → 4d6:6 → ReRoll → 2d6:6 → Explode

`4d6:6` означает четыре кубика со значением 6.

`Explode` — частный случай Add и в MVP не реализуется (в примере — иллюстративно).

Операции в истории визуально различаются оттенками. Соответствующие кубики получают те же оттенки, чтобы было понятно, какие результаты относятся к конкретной операции.

На экране отображается несколько последних строк истории.

**History** открывает полную историю игровой сессии. Последовательности бросков группируются по времени и получают таймкоды.

## Счётчик

Верхняя строка отображает три сегмента по порядку: **Всего → изменения → Выделено**.

- общее количество кубиков на столе;
- изменения с последнего Roll или Clear (Move, Add, Delete, ReRoll);
- количество выбранных кубиков.

После Roll или Clear сегмент изменений пуст до следующей модификации.

## Game Feel

Приложение использует 3D-кубики, анимации, звуки, частицы и визуальные эффекты.

Основные реакции:
- добавление кубиков — короткий приятный звук;
- удаление — звук движения воздуха;
- бросок — звук падающих костей;
- успешный ReRoll — усиленный звук и частицы;
- особенно удачные и неудачные результаты могут получать отдельные визуальные и звуковые реакции.

Визуальный стиль — трёхмерная сцена с обработкой изображения, создающей ощущение пиксель-арта.

- **Menu** — настройки и дополнительные функции.

## Платформа

Базовая версия должна:
- работать как веб-приложение;
- поддерживать работу офлайн после сохранения на устройстве;
- запускаться практически мгновенно;
- экономно расходовать заряд аккумулятора;
- работать на разных платформах.

## Оффлайн и установка (PWA)

Оффлайн даёт Service Worker: при первом открытии он кэширует весь
app shell (JS, CSS, модель, звуки), после чего приложение работает без
сервера. Service Worker регистрируется только в secure context — HTTPS
или `localhost`. Поэтому `npm run dev` через локальную сеть по HTTP
оффлайн не даёт.

### Локальный тест на телефоне (Wi-Fi)

1. Установить mkcert и сгенерировать сертификат:
   ```sh
   brew install mkcert
   make cert
   ```
2. Доверить корневой CA mkcert на телефоне:
   - `mkcert -CAROOT` покажет путь к `rootCA.pem`;
   - iOS: перенести файл (AirDrop) → Установить профиль → Настройки →
     Основные → Об этом устройстве → Доверие сертификатам → включить;
   - Android: Настройки → Безопасность → Установить сертификат CA.
3. Собрать и запустить по HTTPS:
   ```sh
   make serve
   ```
4. На телефоне открыть `https://<IP из вывода>:8443` → «Add to Home
   Screen». После первой загрузки сервер можно остановить — приложение
   продолжит работать.

### Хостинг в интернете

Деплой настроен через GitHub Actions на GitHub Pages:

1. Включить Pages: Settings → Pages → Source = «GitHub Actions».
2. Push в `main` → workflow соберёт и выложит `dist`.
3. Готовый URL: https://liquid245.github.io/dice_flow/
4. Установить PWA на устройство → оффлайн работает.

Обновление версии происходит автоматически (`registerType: autoUpdate`):
при онлайне Service Worker подхватывает новую сборку при следующей
загрузке.

## Будущее расширение

Архитектура должна позволять в будущем добавлять:
- различные типы кубиков;
- произвольное количество граней;
- произвольные значения и свойства граней;
- специальные варгеймовые кубики;
- дополнительные визуальные наборы;
- наборы звуков и эффектов;
- внутриигровые покупки;
- обновление приложения без полной переустановки.

Эти возможности не входят в MVP.
